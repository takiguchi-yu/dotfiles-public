## 成果物は、渡す前にサブエージェントのレビューを通す

成果物は、外部に書き込む前・ユーザーに報告する前に、`deliverable-reviewer` サブエージェントのレビューを通す。時機は下の表で決まる。
自分で書いたものは自分の前提で読んでしまうので、前提を持たない読み手を 1 回挟む。
レビューを回すのはメインセッション。サブエージェントとして動いているときは、外部への書き込みを下書きとして scratchpad に置いて返し、レビューと書き込みは呼び出し元に任せる。

### 対象とタイミング

| 成果物 | レビューするタイミング | レビュー役に渡すもの |
| --- | --- | --- |
| ローカルのファイル（コード・文書・設定） | 書いた後、commit・push・PR の作成と報告の前 | 変更したファイルの一覧と差分（`git diff` を scratchpad に保存したものなど） |
| 外部への書き込み（下の定義） | **書き込む前**。下書きの段階 | scratchpad に置いた下書き（値の変更・状態の遷移・削除なら、対象と変更前後の値の一覧）と、書き込み先の現状のスナップショット（追記・上書きなら必須） |

外部への書き込みは、Sheets・Docs・Jira・Confluence・Slack・メール・GitHub の Issue や PR などの外部サービスで、内容や値が変わる操作すべてを指す（git の commit・push は上のローカルのファイルの行で扱う）。本文・コメントの作成と編集、優先度や状態などの値の変更、状態の遷移、削除、ユーザーの指摘を受けた直しを含み、MCP 経由も `gh` などの Bash 経由も同じに扱う。1 項目だけの変更も、「出力して」「直して」と頼まれた書き込みも対象にする。

外部に書くときは、下書きを作る → レビュー → 直す → 書き込む → 書いた結果を自分で読み返す、の順に進める。

次のものは対象外とする。

- scratchpad の一時ファイル、メモリのファイル、ロックファイルなどの生成物
- スキルの手順の中でサブエージェントのレビューを実際に回したとき（complete-task・pr-review・code-review・pr-comments・consistency-check など）。スキルがレビューの手順を省いたときは、この規定でレビューする
- ユーザーがその作業でレビュー不要と言ったとき

### 確認を省く範囲

レビューを通した外部への書き込みは、ユーザーの確認を挟まずに実行する。レビューを外向きの確認の代わりにする。
省くのは依頼の範囲内の書き込みの確認だけで、commit・push・PR の作成は依頼されたときだけ行う。
スキルの手順に確認の段があれば、その手順に従う。

| 操作 | 確認 |
| --- | --- |
| 下の行に当たらない外部への書き込み（作成・追記・上書き・送信・値の変更・状態の遷移） | 省く |
| 依頼に無い既存の内容が消える上書き（スナップショットにあって、書き込み後に無くなるもの） | 削除として扱い、取る |
| 削除、課金、本番反映、公開（共有範囲を広げる変更） | レビューを通した後に取る（@DECIDE.md） |
| 書き込む時点で Blocker が残っている（直さないと判断したものを含む） | 書き込まずに聞く |

### レビュー役への渡し方

- **渡すのは事実だけにする。** ユーザーの依頼（言葉どおりの要約）、完了条件、成果物の場所、事実主張の根拠にした一次情報の場所。自分の評価まで渡すと、レビュー役はそれを追認する
- 渡すファイルは scratchpad に置き、絶対パスで指定する
- 1 ターンに成果物が複数あれば、1 回のレビューにまとめる

### 指摘を受けたら

- **Blocker と Major は直す。**
- Blocker か Major を直したときだけ、直した差分を再レビューに回す。再レビューは 1 回まで

### 報告に残すこと

報告に「レビュー: 指摘 N 件（対応 M・見送り K・未解決 U）」と 1 行書く。見送りと未解決には、1 件ずつ理由を添える。
レビューを飛ばしたときは、上の対象外のどれに当たるかを 1 行書く。
