## 情報は種類ごとの置き場に書く（HWWWn）

成果物の**本体**には**今の姿**を書き、**経緯**は commit・PR・チケットに書く。読み手が本体だけで、何が言いたいか・どこを見ればよいかを掴めるようにするため。
t_wada の HWWWn の原則（コードには How、テストコードには What、コミットログには Why、コードコメントには Why not）を、コード以外の出力にも広げたもの。

### 置き場

| 情報 | 置き場 |
| --- | --- |
| 今の姿 | 本体（コード・テスト・文書・ページ、報告・PR・チケットでは本文）。コードは How、テストは What（何を保証するか） |
| 今の姿の理由、あえてやらなかったこと（Why not） | 本体。コードではコメント |
| 経緯 | commit・PR・チケット。どれも無い出力（Slack・メール・Confluence・Docs・チケットの無い作業）では書かない |

**経緯**は、変更の前を知っている人にしか意味が無い時系列の話を指す。試した順番、途中の失敗、以前の姿、指摘を受けて直したこと、途中で変えたこととその理由など。
今の版だけを読む人に要るものは理由で、経緯に入らない。確定しなかった結論を支える試した範囲と結果（@EVIDENCE.md の 4）も、結論に要るので理由の側に入る。

### 報告・PR・チケットの形

本文を先に、`## 記録` を最後の節に書く。

| 部分 | 書くもの |
| --- | --- |
| 本文（@PREP.md の順） | 結論、変更点（変更前後、採用した設計パターン）、見る場所（`path:line`・URL）、次の一手と残課題（未解決のレビュー指摘を含む。`## 記録` の件数の行と両方に書く）。確かめた範囲と置いた仮定は、結論の横に置く。ほかの規定が報告に載せると定めたもの（@SPEC.md の仕様など）も、下の行に無ければここに置く |
| `## 記録` | 自分で決めたもの（@DECIDE.md）、設計パスと見送ったパターン（@DESIGN.md）、既存の慣習に合わせた乖離（@PRACTICE.md・@SPEC.md）、レビューの結果（@REVIEW.md の「報告に残すこと」）。PR・チケットでは経緯もここに書く |

- `## 記録` に書くものが無ければ、節ごと省く
- `## 記録` は @MARKDOWN.md の「節の数」に数えない。見出しの無い短い報告では、見出しを付けずに最後の段落に置く
- チケットでは、後から足すコメントを `## 記録` の後ろに続ける（@ISSUE.md）

完了条件: 本体に経緯が 0 件。`## 記録` に置くものが、`## 記録` の外に 0 件。
