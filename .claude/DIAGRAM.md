## 構造のある説明は、図を描いて本文と番号で結ぶ

アーキテクチャ・仕組み・手順・状態を説明するときは、**頼まれていなくても図を描き**、本文は図の番号を辿る形で書く。
描くときは `diagram` スキルを読む（依頼が無くても）。ターミナルの応答と markdown に載せる図は `diagram` で描く。Artifact・HTML ページの図は `artifact-diagramming` か `archify` で描く。
罫線の箱は必ず `mmd2txt` に描かせる（日本語と罫線の幅を手で数えると右端がずれる）。手で描くのは `[1] A --> [2] B` のような枠の無い 1 行の図だけ。

### 描く条件

次のどれかに当たったら描く。

| 内容の形 | 図の型 |
| --- | --- |
| 3 つ以上の要素が依存し合う | `graph`（構成図） |
| 複数の役者を 3 手順以上またぐ | `sequenceDiagram` |
| 3 つ以上の状態が遷移する | `graph`＋矢印ラベル |
| 3 つ以上の実体が関連する | `graph`＋矢印ラベル |

どれにも当たらない説明（要素が 2 つ以下、1 人の役者で一直線に進む手順）は、番号付きの箇条書きで書く。比べる内容は、下の節のとおり表にする。

### 本文と図を番号で結ぶ

- 図の箱と矢印のラベルに、**説明する順に** `[1] [2] [3]…` を振る。順番は図の向き（左→右、上→下）に揃える。丸数字（①）は端末で 1 マスに縮んで読みにくいので使わない
- 応答では、結論の 1 文（@PREP.md の Point）のすぐ後に図を置き、本文はその後に書く
- 本文の各段落・各項目は、図と同じ番号で始める（「[1] 利用者が…」）。図の中の名前と本文の用語は同じ語にする
- **完了条件: 図の番号と本文の番号が 1 対 1 で対応している。** 図にしか無い番号、本文にしか無い番号が 0 件になるまで直す

## 人に読ませる文書は、図表を主にして文章を短くする

対象: ターミナルの応答、Artifact・Docs・HTML ページ、Issue や PR の本文。出し先の既定はターミナルの応答で、Artifact・Docs にするのは頼まれたときだけ（URL を追い続ける手間が増えるため）。ツール説明にある「他者向けの成果物は頼まれなくても公開する」より、この規定を優先する。

- 比べるもの（今と提案・案ごとの良し悪し・値の対応）は表にする
- 流れ・関係・状態は、上の「描く条件」に当たれば図にする
- スキーマや入出力が変わる説明には、変更前後の定義と値の例を並べる
- 地の文は、表や図を読む前提を 1〜2 文で書くだけ

完了条件: 3 文を超える段落が 0 件。比較・対応を書いた節には表が、描く条件に当たる節には図が、スキーマや入出力の変更を書いた節には変更前後の定義と値の例がある。
