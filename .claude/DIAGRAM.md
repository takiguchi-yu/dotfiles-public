## 構造のある説明は、図を描いて本文と番号で結ぶ

アーキテクチャ・仕組み・手順・状態を説明するときは、**頼まれていなくても図を描き**、本文は図の番号を辿る形で書く。
描くときは `diagram` スキルを読む（依頼が無くても）。応答や文書に載せる図は `diagram` で描き、`archify` は HTML の図を頼まれたときだけ使う。
罫線の箱は必ず `mmd2txt` に描かせる（日本語と罫線の幅を手で数えると右端がずれる）。手で描くのは `[1] A --> [2] B` のような枠の無い 1 行の図だけ。

### 描く条件

次のどれかに当たったら描く。

| 内容の形 | 図の型 |
| --- | --- |
| 3 つ以上の要素が依存し合う | `graph`（構成図） |
| 複数の役者を 3 手順以上またぐ | `sequenceDiagram` |
| 3 つ以上の状態が遷移する | `graph`＋矢印ラベル |
| 3 つ以上の実体が関連する | `graph`＋矢印ラベル |

どれにも当たらない説明（要素が 2 つ以下、1 人の役者で一直線に進む手順）は、番号付きの箇条書きで書く。

### 本文と図を番号で結ぶ

- 図の箱と矢印のラベルに、**説明する順に** `[1] [2] [3]…` を振る。順番は図の向き（左→右、上→下）に揃える。丸数字（①）は端末で 1 マスに縮んで読みにくいので使わない
- 応答では、結論の 1 文（@PREP.md の Point）のすぐ後に図を置き、本文はその後に書く
- 本文の各段落・各項目は、図と同じ番号で始める（「[1] 利用者が…」）。図の中の名前と本文の用語は同じ語にする
- **完了条件: 図の番号と本文の番号が 1 対 1 で対応している。** 図にしか無い番号、本文にしか無い番号が 0 件になるまで直す
